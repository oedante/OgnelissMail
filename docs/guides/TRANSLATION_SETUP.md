# Перевод писем на устройстве (1.9.x)

Просьба владельца 31.10.2026: перевод входящих писем и своего текста в
письме («написал на русском — перевёл на английский, можно оставить оба
текста»). Перевод выполняется на телефоне, текст писем в интернет не уходит.

## Что где работает

| Платформа | Движок | Языки | Скачивание языков |
|---|---|---|---|
| Android | Google ML Kit (перевод + определение языка) | ~59 | приложение, при первом переводе (~30 МБ на язык), можно «только по Wi-Fi»; удалить — «Настройки → Почта → Перевод → Языки на устройстве» |
| iPhone, iPad (iOS 18+) | Apple Translation | ~20 | сама iOS (системное окно «Скачать языки?»); удалить — «Настройки iOS → Приложения → Перевод» |
| iOS 15–17 | — | — | перевод недоступен, в настройках так и написано |
| Mac (macOS 15+) | Apple Translation | ~20 | сама macOS |
| Windows (2.2.0) | Bergamot (Mozilla) в скрытом WebView2; язык письма — свой определитель (алфавит и частые слова) | 15 с английским (болгарский, чешский, немецкий, испанский, эстонский, персидский, французский, итальянский, нидерландский, польский, португальский, русский, украинский; исландский и норвежский — только на английский), другие пары — через английский | приложение, с сервера Ogneliss (~45 МБ на язык: пары с английского и на английский), проверка sha256; удалить — там же, где на Android |
| Linux, веб | — | — | бесплатного движка на устройстве нет, пункты скрыты |

Код: `lib/services/translation/` (разбор HTML на куски, выбор языков, канал
`ogneliss/translate`), `lib/features/mail/widgets/mail_translation.dart`
(плашка в письме), `lib/features/compose/widgets/compose_translate.dart`
(перевод своего письма), `lib/features/settings/widgets/translation_settings_section.dart`,
Android — `android/app/src/main/kotlin/com/ogneliss/mail/TranslationBridge.kt`,
iOS — конец `ios/Runner/AppDelegate.swift`.

## Что сделать владельцу

### Xcode (iPhone, iPad)

Включать ничего не нужно: новых файлов, возможностей (capabilities) и
разрешений нет, код — в уже подключённом `AppDelegate.swift`. Нужен Xcode 16
или новее (SDK iOS 18 с фреймворком Translation); в старом Xcode код
перевода не собирается и перевод просто будет недоступен (`#if canImport`).

Проверить один раз на устройстве с **iOS 15–17**, что приложение
запускается. Фреймворк Translation на таких версиях отсутствует; компоновщик
подключает его как необязательный сам, потому что весь код перевода — под
`#available(iOS 18.0, *)`. Если всё же при запуске на iOS 15–17 будет
падение с «Library not loaded: …/Translation.framework»:

1. Xcode → проект Runner → цель **Runner** → вкладка **Build Phases**.
2. **Link Binary With Libraries** → «+» → **Translation.framework** → Add.
3. В той же строке в столбце **Status** выбрать **Optional**.
4. Собрать заново.

### Google Play и описание приложения (Android)

Условия ML Kit на перевод требуют соблюдать правила атрибуции Google Cloud
Translation (cloud.google.com/translate/attribution):

- рядом с переводом — подпись Google: в приложении есть строка
  «Переведено Google» под плашкой перевода и пояснение в «Настройки →
  Почта → Перевод»; если Google потребует фирменный значок «Translated by
  Google» — его можно подставить вместо строки (файлы дают на странице
  атрибуции, это знак Google — использовать только по их правилам);
- в **описании приложения в магазине** и в справке указать, что перевод
  выполняется с помощью Google Translate, со ссылкой на
  https://cloud.google.com/translate — например, строкой в конце описания:
  «Перевод писем на Android выполняется на устройстве с помощью Google
  Translate (ML Kit): https://cloud.google.com/translate»;
- в названии приложения слова Google не использовать (не используем).

Политика конфиденциальности и «Безопасность данных» в Play Console: ML Kit
отправляет в Google статистику производительности и использования API
(не текст писем). Условия ML Kit обязывают сообщить об этом пользователям —
добавить фразу в политику конфиденциальности; в форме «Безопасность данных»
отметить «Диагностика приложения / сведения о производительности»
(передаётся Google, не продаётся).

Размер APK: движок перевода и определения языка добавляют несколько МБ
(модели языков в APK не входят).

На устройствах без сервисов Google (часть телефонов из RuStore) скачивание
языков может не работать — тогда приложение пишет «Не удалось перевести».

## Как пользоваться

- **Входящее письмо**: если язык письма не язык приложения — плашка «Язык
  письма: английский · Перевести». Перевод заменяет текст письма (ссылки,
  оформление, таблицы рассылок остаются), «Показать оригинал» — обратно.
  «⋮» на плашке — «Не переводить с языка …» или закрыть. Пункт
  «Перевести» есть и в меню письма.
- **Своё письмо**: «⋮ → Перевести» на экране «Написать» → язык (первым —
  язык собеседника по цитате письма, затем недавние) → «Заменить текст»
  или «Оставить оба текста» (сначала оригинал или сначала перевод; выбор
  запоминается). Переводится только свой текст с приветствием; подпись и
  цитата не переводятся. Вернуть — «Вернуть» в строке сообщения или
  «Отменить» в редакторе.
- **Настройки → Почта → Перевод**: предлагать перевод, «Не переводить с
  языков», «Скачивать только по Wi-Fi», скачанные языки (Android).

## Windows: Bergamot (2.2.0)

Решение владельца 09.11.2026: движок — в сборке Windows, модели — с
ogneliss.ru (не у Google и не у Mozilla напрямую).

Как устроено:

- **Движок** — npm-пакет `@browsermt/bergamot-translator` 0.4.9 (MPL-2.0):
  translator.js, worker и WebAssembly (~5 МБ). В git его нет: перед сборкой
  `tool/bergamot/fetch_engine.sh` (CI) или `tool/bergamot/fetch_engine.ps1`
  (`scripts/build_windows.ps1`, `scripts/setup.ps1`) скачивает пакет из npm и
  сверяет пакет и каждый файл с `tool/bergamot/engine.sha256`; строка в конце
  `windows/CMakeLists.txt` подключает `tool/bergamot/bergamot.cmake`, и при
  установке сборки файлы попадают в `data\bergamot` рядом с exe вместе с
  текстами лицензий. Нет папки — перевода на этом компьютере нет, как раньше.
- **Работа** — скрытый WebView2 (flutter_inappwebview) открывает страницу
  локального сервера приложения: только 127.0.0.1, порт выбирает система,
  все адреса под случайным ключом, проверка Host, только GET; CSP страницы
  запрещает запросы наружу. Текст писем передаётся в движок как данные.
  Через 5 минут без переводов WebView закрывается (модели занимают сотни МБ).
  Код — `lib/services/translation/bergamot/`.
- **Модели** — Firefox Translations (Mozilla, MPL-2.0), набор 0.3.3.
  Приложение читает `https://ogneliss.ru/mail/translate/v1/index.json`
  (формат registry.json Bergamot) не чаще раза в неделю, скачивает пары в
  папку данных приложения (`%APPDATA%\com.ogneliss\Ogneliss Mail\translate\bergamot`)
  и сверяет каждый файл с sha256 из списка. Без сети список языков — встроенный.
- **Язык письма** — `lib/services/translation/lang_detect.dart` (Bergamot языки
  не определяет); названия языков — CLDR (`language_names.g.dart`).

### Что сделать владельцу

1. **Сервер ogneliss.ru** — выложить модели: `server/translate-models/README.md`
   (скрипт скачивает ~670 МБ из хранилища Bergamot, проверяет sha256,
   запускает раздачу nginx; раздел `/mail/translate/` в Nginx Proxy Manager).
   Пока моделей на сервере нет, перевод на Windows виден, но языки не
   скачаются («Не удалось скачать языки»).
2. **Сборка Windows** — ничего вручную: `scripts/build_windows.ps1` сам
   скачает движок (нужен доступ к registry.npmjs.org и tar.exe, он есть в
   Windows 10 1803+). В журнале сборки — «Bergamot 0.4.9: …».
3. **Проверить на компьютере**: открыть письмо на английском → «Перевести» →
   «Скачать» (русский и английский, ~45 МБ) → перевод. «Настройки → Почта →
   Перевод → Языки на устройстве» — список скачанных, удаление.
4. **Политика конфиденциальности** — по желанию добавить: «На Windows языки
   для перевода скачиваются с сервера Ogneliss; текст писем не передаётся».

Проверено в этой сессии: весь путь (локальный сервер приложения → Chromium
→ движок 0.4.9 → модели с «сервера») — en→ru и nb→ru через английский,
CSP блокирует запросы наружу. В самом WebView2 на Windows не проверялось.

Оговорки: движок 2022 года (новых выпусков npm нет), набор моделей Mozilla
0.3.3 в архиве с 15.12.2025 — работают, но обновлений не будет. Новые модели
Mozilla (`mozilla/translations`) — другой формат файлов; переход — отдельной
задачей.
