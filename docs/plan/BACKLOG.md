# На развитие (записано по просьбе владельца)

Пункты, которые владелец попросил записать на будущее. В работу берутся по
его слову.

## Несколько серверов на разных хостингах (01.11.2026)

**Задача.** Сейчас всё серверное — на одном сервере `ogneliss.ru`:

- вход через OAuth и обновление токенов;
- сигналы проверки почты;
- логотипы BIMI.

Если хостинг недоступен, пользователи Gmail, Яндекса, Mail.ru и Outlook не
смогут войти, а через час, когда истечёт токен доступа, перестанут получать
почту. Нужны запасные серверы у других хостингов.

**Что учесть по каждой службе:**

- **OAuth-прокси** (`server/oauth-proxy`) — самое важное.
  - `ENC_SECRET` должен быть одинаковым на всех серверах. Токен обновления,
    зашифрованный одним сервером, должен расшифровываться другим, иначе
    после переключения все OAuth-ящики потребуют входа заново.
  - `PROXY_API_KEY` (он же `OAUTH_PROXY_KEY` в сборке) и `STATE_SECRET`
    тоже одинаковые.
  - Адрес возврата `redirect_uri` (`<BASE_URL>/callback`) нужно
    зарегистрировать в консолях Google, Microsoft, Яндекса и Mail.ru для
    каждого адреса сервера.
  - Готовые токены после входа лежат 2 минуты в памяти того сервера,
    который принял код. Поэтому вход целиком идёт через один сервер; на
    запасной переключается только следующий вход или обновление токена.
- **Служба сигналов** (`server/push-relay`).
  - Хранит токены устройств. Есть два варианта:
    - приложение регистрируется на основном сервере и при его недоступности
      перерегистрируется на запасном;
    - регистрируется на обоих, а запасной шлёт сигналы, только если
      основной молчит.
  - Ключ Apple (`.p8`) и ключ Firebase нужны на каждом сервере.
- **BIMI** (`/bimi` в OAuth-прокси) — без состояния, только кэш:
  переключается без условий.

**Как переключаться — два пути:**

1. **В приложении — рекомендую.**
   - В сборке задаётся список адресов вместо одного: `OAUTH_PROXY_URLS`,
     `PUSH_RELAY_URLS`.
   - При сетевой ошибке или ответе 5xx приложение берёт следующий адрес и
     запоминает рабочий.
   - Всё под контролем владельца, посредники не нужны.
2. **На уровне DNS:** один адрес, проверка доступности у DNS-провайдера и
   переключение записей. Приложение не меняется, но появляется зависимость
   от DNS-провайдера, иногда платная. По правилу CLAUDE.md это сначала
   обсудить с владельцем. Переключение занимает минуты из-за времени жизни
   записей.

**Ещё:**

- **Скрипты установки:** `install-oauth-proxy.sh` и `install-push-relay.sh`
  должны уметь ставить запасной сервер с теми же секретами. Например,
  команда `export-secrets` на основном и `install --secrets` на запасном.
- **Наблюдение:** команда `check` по расписанию на каждом сервере и
  уведомление владельцу, если сервер не отвечает.
- **Политика конфиденциальности:** перечислить серверы и страны
  размещения.
- **Персональные данные:** журналы с IP-адресами — персональные данные.
  Перед выбором хостинга за рубежом проверить требования 152-ФЗ о
  хранении данных граждан России.
- **Своя сборка** (`guides/OWN_VERSION.md`): список адресов вместо одного.
