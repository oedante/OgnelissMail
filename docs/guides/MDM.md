# Ogneliss Mail в системе управления устройствами (MDM)

Для ИТ-службы. С версии 1.10.5 приложение принимает настройки организации
из MDM:

- **Android** — управляемые настройки Android Enterprise (managed
  configurations). Приложение нужно ставить из управляемого Google Play
  (рабочий профиль или полностью управляемое устройство).
- **iPhone и iPad** — Managed App Configuration. Приложение ставится через
  MDM как управляемое (Apple Business Manager / VPP или ручная установка
  из консоли MDM).

На компьютерах (Windows, macOS, Linux) настроек MDM нет.

Приложение бесплатное и с открытым кодом: проверить, что делает каждый
ключ, можно по исходникам. Разбор ключей —
`lib/services/security/managed_config.dart`, список для Android —
`android/app/src/main/res/xml/app_restrictions.xml`.

## Ключи

Все ключи необязательны: что не задано, то пользователь настраивает сам.

| Ключ | Тип | Что делает |
|---|---|---|
| `org_name` | строка | Название организации в «Настройки → Управляется организацией». |
| `support_contact` | строка | Контакт ИТ-поддержки там же. Телефон, адрес почты или ссылка `https://…` открываются нажатием. |
| `account_email` | строка | Адрес ящика: на экране входа он уже вписан, пользователю остаётся пароль. |
| `account_protocol` | строка | `auto` (по умолчанию), `exchange` или `imap`. `eas` и `ews` понимаются как `exchange`: ActiveSync или EWS приложение выбирает само, как при обычном входе. |
| `account_server` | строка | Сервер Exchange: адрес или URL, например `mail.example.ru`. |
| `account_username` | строка | Имя для входа, если оно не совпадает с адресом. |
| `account_domain` | строка | Домен Windows для входа в Exchange. |
| `imap_server`, `imap_port` | строка, число | Сервер и порт IMAP для `imap` (порт по умолчанию 993, SSL). |
| `smtp_server`, `smtp_port` | строка, число | Сервер и порт SMTP для `imap` (порт по умолчанию 587 со STARTTLS; 465 — SSL). |
| `allowed_domains` | строка | Через запятую: `example.ru, example.com`. Добавить можно только ящики этих доменов и их поддоменов, при любом способе входа (пароль, Google, Microsoft). Пусто — любые. |
| `require_app_lock` | да/нет | Обязательный PIN приложения: без него почта не открывается, выключить его нельзя. |
| `min_pin_length` | число | Длина этого PIN: от 4 до 6 (по умолчанию 4). |
| `block_screenshots` | да/нет | Запрет снимков и записи экрана, показа на внешнем экране и миниатюры в «Недавних». **Только Android**: iOS не даёт приложениям запрещать снимки экрана. |
| `block_share` | да/нет | Запрет «Поделиться» (в том числе в облака), сохранения в файлы и «Загрузки», PDF и печати письма, перетаскивания вложений из письма в другие приложения (с 1.15.0). |
| `block_open_in` | да/нет | Вложения не открываются в других приложениях и не перетаскиваются в них (с 1.15.0). Учтите: то, что приложение не показывает само (Word, Excel и т. п.), тогда не откроется вовсе. PDF и картинки приложение показывает само. |
| `block_copy` | да/нет | Текст писем нельзя выделить и скопировать. Адреса, ссылки и текст своего письма копируются как обычно. |
| `hide_notification_content` | да/нет | В уведомлениях нет отправителя, темы и текста — только «Новое сообщение». Быстрых ответов с текстом тоже нет. |
| `block_weather` | да/нет | В «Моём дне» нет погоды: приложение не обращается к сервисам погоды (MET Norway) и поиска города (OpenStreetMap). По умолчанию погода и так выключена — её включает сам пользователь выбором города (с 1.15.1). |
| `max_sync_days` | число | Почта на устройстве — не больше стольких дней (с 2.2.0). Ящики с периодом «вся почта» или длиннее получают этот; в «Период синхронизации» дальше предела не выбрать. 0 или нет ключа — без предела. |
| `block_attachment_download` | да/нет | Вложения нельзя открыть (и предпросмотром), сохранить, перетащить или отправить в другое приложение (с 2.2.0). Пересылать письма с вложениями можно: файлы не попадают к человеку. |
| `pin_timeout_minutes` | число | Приложение закрывается PIN-кодом через столько минут без работы, 1–60 (с 2.2.0). Если политика Exchange (MaxInactivityTimeDeviceLock) задаёт меньше — действует она. Работает, когда PIN приложения задан (вместе с `require_app_lock`). |
| `allow_biometrics` | да/нет | Вход по отпечатку и лицу; по умолчанию — да (с 2.2.0). «Нет» — только PIN приложения. |
| `block_external_services` | да/нет | Без внешних служб (с 2.2.0): нет погоды (как `block_weather`), логотипов отправителей (BIMI), сигналов о новой почте через сервер Ogneliss — регистрация на нём снимается — и сервера входа Ogneliss. Новая почта приходит по соединению с сервером почты и плановым проверкам. Ящики, которые входят через сервер входа (Яндекс, Mail.ru, Exchange Online, если в сборке нет своего клиента Microsoft), перестают обновлять вход и просят войти снова; тогда их добавляют паролем приложения (IMAP/SMTP). |
| `account_locked` | да/нет | Ящик из `account_email` закреплён (с 2.2.0): его нельзя удалить из приложения, нельзя изменить сервер и вход. Остальные ящики пользователь ведёт как обычно. |
| `account_transport` | строка | `auto` (по умолчанию), `eas` (ActiveSync) или `ews` — протокол подключения к своему серверу Exchange (с 2.2.0). Приложение не переключается на другой, даже если этот не отвечает. Exchange Online со входом Microsoft не затрагивается: там протокол выбирает Microsoft Graph. |
| `require_tls` | да/нет | Только шифрованные соединения (с 2.2.0): IMAP и SMTP без SSL или STARTTLS не подключаются, пользователь видит, что включить в настройках ящика. Exchange и так работает только по HTTPS. |
| `trusted_ca_pem` | строка | Корневые сертификаты организации в формате PEM, один или несколько подряд (с 2.2.0). Серверам почты, подписанным ими, приложение доверяет — как сертификатам, загруженным в «Настройки → Безопасность → Сертификаты ЦС». |
| `allow_user_cert_trust` | да/нет | Может ли пользователь сам доверять сертификатам; по умолчанию — да (с 2.2.0). «Нет» — решения пользователя не действуют, и прежние тоже: нельзя загрузить сертификат ЦС, принять сертификат сервера в «Доверять?», задать «доверенный домен», включить ЦС Минцифры; сертификаты, установленные в устройство, приложение не принимает. Действуют только системные и `trusted_ca_pem`, закрепление сертификатов — как обычно. На iPhone сертификат из профиля с полным доверием система считает своим — его установку ограничивает MDM. |
| `block_device_contacts` | да/нет | Контакты не переносятся в «Контакты» устройства и обратно (с 2.2.0). |
| `block_device_calendar` | да/нет | Встречи не переносятся в «Календарь» устройства (с 2.2.0). |

«Да/нет» — логическое значение. Строки `true`, `1`, `yes` тоже
понимаются как «да».

Что включено, пользователь видит в «Настройки → Управляется
организацией». На запрещённое действие приложение отвечает строкой
«Запрещено политикой вашей организации».

## Android Enterprise

Ключи с подписями появляются в консоли MDM сами, после того как
приложение одобрено в управляемом Google Play. Подписи — по-русски или
по-английски.

Новые настройки приходят в работающее приложение сразу (системное
событие `ACTION_APPLICATION_RESTRICTIONS_CHANGED`), а при следующем
запуске читаются заново.

## iOS: Managed App Configuration

Словарь настроек задаётся в консоли MDM для приложения
`com.ogneliss.mail`. Пример (формат plist, его принимает большинство
консолей):

```xml
<dict>
  <key>org_name</key>
  <string>ООО «Ромашка»</string>
  <key>support_contact</key>
  <string>+7 495 123-45-67</string>
  <key>account_email</key>
  <string>$EMAIL$</string>
  <key>account_protocol</key>
  <string>exchange</string>
  <key>account_server</key>
  <string>mail.romashka.ru</string>
  <key>allowed_domains</key>
  <string>romashka.ru</string>
  <key>require_app_lock</key>
  <true/>
  <key>min_pin_length</key>
  <integer>6</integer>
  <key>block_share</key>
  <true/>
  <key>block_open_in</key>
  <false/>
  <key>block_copy</key>
  <true/>
  <key>hide_notification_content</key>
  <true/>
  <key>block_weather</key>
  <true/>
  <key>max_sync_days</key>
  <integer>90</integer>
  <key>pin_timeout_minutes</key>
  <integer>5</integer>
  <key>allow_biometrics</key>
  <false/>
  <key>account_locked</key>
  <true/>
  <key>account_transport</key>
  <string>eas</string>
  <key>require_tls</key>
  <true/>
  <key>trusted_ca_pem</key>
  <string>-----BEGIN CERTIFICATE-----
MIIDdzCCAl+gAwIBAgIE…
-----END CERTIFICATE-----</string>
  <key>allow_user_cert_trust</key>
  <false/>
</dict>
```

`$EMAIL$` — подстановка адреса пользователя. Так она называется в
Microsoft Intune; в других консолях имя переменной своё.

Изменения приложение замечает, пока оно открыто, и при каждом запуске.

## Что остаётся за MDM и сервером

- **Код блокировки телефона, шифрование устройства** — политика паролей
  самого MDM. Политику Exchange (EAS Provision: пароль, тайм-аут
  блокировки) приложение тоже выполняет.
- **Удалённое стирание** — командой Exchange (RemoteWipe и
  AccountOnlyRemoteWipe, EAS 16.1) или средствами MDM: удаление
  управляемого приложения или рабочего профиля стирает его данные.
- **Резервные копии** — данные приложения из резервных копий Android
  исключены (`allowBackup=false`), на iPhone — из резервных копий iCloud.
- **Передача файлов между управляемыми и личными приложениями** — в
  рабочем профиле Android и в управляемых приложениях iOS это
  дополнительно ограничивает сама система (например, Managed Open In).
