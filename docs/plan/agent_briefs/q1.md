## 2. Android emulator integration tests (on demand + tags)
Goal: catch regressions we otherwise only see on the owner's phone: selection drops/handles misplaced in mail and editor (touch coordinates vs content), mail zoom/fit-to-width/height, editor loading.
- integration_test/ has a basic app_test.dart. Add focused tests (Android only) that pump the real widgets without accounts:
  - MailHtmlView (lib/features/mail/widgets/mail_html_view.dart) with sample documents: a normal message, a 600–700 px wide newsletter, a message with an image and a link. Check: the WebView reports zoom scale (onZoomScaleChanged) consistent with fit/100%, measured height within tolerance of expected, no blank tail after "По ширине экрана"/"Обычный размер" toggles. Touch mapping (what selection drops depend on): tap at the on-screen centre of a known link and of an image and check InAppWebViewController.getHitTestResult() type (SRC_ANCHOR / IMAGE) — this proves Flutter touch coordinates map to the right content point under UiZoomUndo and UI zoom (test with UiZoom.current 1.0 and 0.85).
  - MailEditor (lib/features/compose/widgets/mail_editor.dart, HugeRTE in a WebView with JS): loads, setHtml/getHtml round trip, tap inside a paragraph puts the caret in that paragraph (evaluate JS for the selection anchor), with UI zoom 0.85 too.
  Read those widgets carefully; you may add small @visibleForTesting hooks if needed (keep them minimal and documented).
- CI job `emulator`: ubuntu-latest + KVM + reactivecircus/android-emulator-runner (check licence), API 34 x86_64 (google_apis), runs `flutter test integration_test/...` on the emulator. Triggered by a new workflow_dispatch boolean input `emulator` and on tags v*. Cache AVD if cheap. Timeout ~45 min.
- You cannot run an emulator here (no KVM probably — check `ls /dev/kvm`). Make sure everything compiles: `flutter analyze` must pass on integration_test too. Keep the tests deterministic (explicit waits on callbacks with timeouts, no fixed sleeps where avoidable).
