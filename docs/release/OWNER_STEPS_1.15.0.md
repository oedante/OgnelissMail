# 1.15.0 — что сделать владельцу (07.11.2026)

1.15.0 (141) — это 1.14.0 (140) плюс перетаскивание вложений наружу и
«Переместить» в письме и в беседе («Что нового» — `STORE_NOTES_1.15.0.md`).
Номер — просьба владельца 07.11.2026: 1.14.0 ушла в тестирование.

**У Apple, Google и на сервере ничего нового делать не нужно.**
`project.pbxproj`, `Runner.entitlements` и `Info.plist` не менялись, новых
прав и возможностей нет. На Android в манифест добавлен закрытый провайдер
данных перетаскивания (без разрешений) — в Play Console заполнять нечего.
Если шаги из `OWNER_STEPS_1.14.0.md` ещё не сделаны, сначала сделайте их.

Новое для вас:

- **Rust (rustup) на каждой машине, где собираете приложение** (шаг 1):
  ядро перетаскивания собирается из исходников на Rust;
- сборка с номером 141 (Android и iOS);
- тексты «Что нового»;
- проверка перетаскивания — на каждой платформе отдельно (шаг 4): пакет
  сам называет себя экспериментальным.

Архив исходников — `ogneliss-mail-1.15.0+141.zip`: распаковывается поверх
прежней папки, настройки Xcode не затирает, `config/dart_defines.json` в
архиве нет (берите прежний).

## 1. Rust на машинах сборки

Пакет super_drag_and_drop (MIT) собирает своё ядро на Rust во время
`flutter build` (и `flutter test`). Нужен только **rustup** — нужную версию
Rust (1.97.1) и цели сборки он скачает сам при первой сборке (один раз,
около 1 ГБ и 5–15 минут; дальше — из кэша). Rust — MIT/Apache-2.0,
бесплатно, в приложение не попадает.

- **Mac** (iPhone, iPad, Mac): в Терминале
  ```bash
  curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
  ```
  ответ по умолчанию (1), затем закройте и откройте Терминал. Проверка:
  `rustup --version`. Xcode находит rustup сам (в `~/.cargo/bin`).
- **Windows:** скачайте `rustup-init.exe` с https://rustup.rs и запустите,
  вариант по умолчанию. Visual Studio с C++ у вас уже есть (её требует
  Flutter для Windows). Откройте новое окно PowerShell, проверка:
  `rustup --version`.
- **Linux:** та же команда, что для Mac; для ядра нужны и заголовки GTK
  (`sudo apt install libgtk-3-dev pkg-config` — те же, что для сборки
  приложения под Linux), в том числе для `flutter test`.
- **GitHub Actions:** rustup на сборщиках GitHub уже есть — ничего делать
  не нужно.

Скрипты `scripts/build_ios.sh`, `build_macos.sh`, `build_windows.ps1`,
`setup.sh`, `setup.ps1` проверяют rustup и, если его нет, пишут, как
поставить.

## 4. Проверить перетаскивание — на каждой платформе

Письмо с двумя вложениями: одно уже открывали (скачано, зелёная галочка),
другое — нет. Если что-то не так, пришлите журнал («Настройки →
Расширенные настройки → Журнал»): ошибки пишутся строкой «Перетаскивание
вложения: …».

1. **Windows:** перетащить мышью плашку вложения на рабочий стол и в папку
   Проводника — появляется файл с именем из письма; не скачанное — тоже
   (скачивается, когда отпустили). Перетащить в окно Word или Outlook.
   **И обратно:** файл из Проводника на окно нового письма — становится
   вложением (приём файлов переведён на тот же пакет).
2. **macOS:** то же с Finder и рабочим столом; файл из Finder — на окно
   нового письма.
3. **Linux:** в файловый менеджер (Nautilus, Dolphin) — не скачанное
   вложение сначала скачивается (кружок на плашке), потом тянется; файл из
   менеджера — на окно нового письма.
4. **Android** (два приложения на разделённом экране, например почта и
   «Файлы» или Google Диск): удержать плашку вложения и перетащить в другое
   приложение. Удержать и отпустить на месте — открывается прежний лист
   (открыть, сохранить, поделиться). Обычное нажатие — открывает вложение,
   как раньше.
5. **iPad** (Split View с «Файлами»): удержать плашку, перетащить в папку
   «Файлов». Удержать и отпустить на месте — лист действий.
6. **iPhone:** долгое нажатие на вложение — лист действий, как раньше
   (перетаскивания на iPhone нет).
7. **MDM** (если есть тестовый): с `block_share` или `block_open_in`
   плашка не перетаскивается.
8. **«Переместить»:** письмо → «Ещё» → «Упорядочить» → «Переместить» →
   папка; беседа → удержать письмо → «Ещё» → «Переместить» → «Переместить»
   → папка. У черновика пункта нет.

Если на какой-то платформе перетаскивание ведёт себя плохо (не начинается,
мешает прокрутке ленты вложений, роняет приложение) — напишите какая: его
можно выключить для неё одной строкой (`AttachmentDragOut.supportedOn`),
не трогая остальные.
