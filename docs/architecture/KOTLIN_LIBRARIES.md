# Готовые библиотеки для Kotlin-версии

Уточнение к `KOTLIN_DEV_GUIDE.md`. В нём я написал, что WBXML и EAS нужно писать
с нуля. Это **не совсем так**: готовая реализация есть, хотя и не в виде
библиотеки с Maven. Ниже — что реально доступно по каждому протоколу.

---

## 1. IMAP / SMTP + OAuth2 — здесь всё хорошо

### Jakarta Mail 2.x
<cite index="25-1">Начиная с Jakarta Mail 2.0.0, стандартная сборка работает на Android напрямую</cite> — отдельный порт не нужен.

```kotlin
dependencies {
    implementation("com.sun.mail:jakarta.mail:2.0.1")
    implementation("com.sun.activation:jakarta.activation:2.0.1")
}

android {
    packagingOptions {
        pickFirst("META-INF/LICENSE.md")
        pickFirst("META-INF/NOTICE.md")
    }
}
```

**Про OAuth2 — важная деталь.** <cite index="25-1">На Android не поддерживается SASL, поэтому свойства `mail.*.sasl.*` не работают. В свежих версиях Jakarta Mail есть встроенная поддержка OAuth2, которая SASL не требует</cite>. То есть пример из документации Google с `mail.imap.sasl.mechanisms = XOAUTH2` на Android **не сработает** — нужен встроенный механизм: токен передаётся как пароль при `store.connect()`.

Что даёт: IMAP, SMTP, POP3, IMAP IDLE (push), разбор MIME, вложения. Минимальный API level 19.

### Альтернатива: код Thunderbird for Android
<cite index="28-1">K-9 Mail переименован в Thunderbird for Android, написан на Java и Kotlin, лицензия Apache 2.0, репозиторий github.com/thunderbird/thunderbird-android</cite>. Там своя реализация IMAP, отлаженная на сотнях серверов. Брать целиком незачем, но как справочник по крайним случаям (нестандартные ответы серверов, кодировки) — полезно.

## 2. EWS — библиотека есть, но с оговорками

### ews-java-api
Официальная библиотека Microsoft (`OfficeDev/ews-java-api`), Maven Central:
`com.microsoft.ews-java-api:ews-java-api:2.0`.

**Три оговорки, которые надо понимать до того, как закладываться:**

1. **Репозиторий архивирован** и находится в режиме поддержки. <cite index="4-1">С 19 июля 2018 года EWS не получает обновлений функциональности; сервис продолжает получать обновления безопасности, но дизайн и возможности не меняются. Это касается и SDK для Java и .NET</cite>.

2. **EWS выводится из эксплуатации для облака.** <cite index="8-1">Microsoft объявила о выводе EWS API для Exchange Online и Office 365; вывод касается только Microsoft 365 и Exchange Online, для локальных версий Exchange это не применяется</cite>. **Для вашего случая это не проблема** — локальный Exchange продолжит работать. Но если когда-нибудь появится переезд в облако, EWS там уже не будет, и понадобится Microsoft Graph.

3. **На Android нужна проверка.** Библиотека тянет Apache HttpClient 4.x, который с Android конфликтует (в API 28+ он удалён из платформы). Варианты: `useLibrary 'org.apache.http.legacy'`, либо форк с OkHttp, либо, как сейчас во Flutter-версии, **свои SOAP-запросы через OkHttp + XmlPullParser**.

**Моя рекомендация:** для локального Exchange взять свою реализацию. Причины: у вас уже отлажены запросы (включая адресацию общих ящиков через `<t:Mailbox>`, чего в типовых примерах нет), объём EWS-части невелик — около 3500 строк, а зависимость от архивированной библиотеки с конфликтующим HTTP-клиентом добавит проблем при сборке.

Библиотеку стоит держать как запасной вариант, если своя реализация упрётся в неочевидное поведение сервера.

## 3. EAS (ActiveSync) — SDK нет, но есть готовый код

### Публичного SDK не существует
<cite index="21-1">ActiveSync — лицензируемая технология, публичного SDK нет. Клиенты, желающие её использовать, должны реализовать протокол по спецификации. Это проприетарный бинарный протокол, с которым работать существенно сложнее, чем с SOAP</cite>.

### ⚠ Лицензирование — проверить до начала работ
<cite index="20-1">Поддержка разработки клиентской части предоставляется только заказчикам с соглашением Premier, лицензировавшим EAS для клиентской разработки. Если планируется коммерциализация приложения, использующего EAS, необходимо получить лицензию от Microsoft — лицензирование строго отслеживается</cite>.

Для внутреннего корпоративного приложения ситуация отличается от публичной продажи, но это вопрос к юристам и к ИТ-службе, а не технический. **Выяснить стоит до того, как потрачены месяцы на реализацию.** Если лицензия окажется проблемой — остаётся EWS, который для локального Exchange покрывает почти всё.

### Готовая реализация на Java: AOSP Exchange
<cite index="17-1">В Android есть стек ActiveSync под лицензией Apache, реализованный на Java: `git clone https://android.googlesource.com/platform/packages/apps/Exchange`. Парсер — `src/com/android/exchange/adapter/Parser.java`, определения кодовых страниц и тегов — `Tags.java`, основная логика протокола — `EasSyncService.java`, синхронизация писем — `EmailSyncAdapter.java`</cite>.

Это официальная реализация Google для штатного почтового клиента Android. Что важно:
- **Apache 2.0** — можно брать и изменять;
- **на Java** — совместимо с Kotlin без прослоек;
- содержит **таблицы кодовых страниц WBXML** — самую скучную и ошибкоопасную часть;
- проверено на миллионах устройств.

Минус: приложение Email удалено из современного AOSP, код лежит в истории и рассчитан на старые версии протокола (12.x–14.x). Потребуется обновление под 14.1/16.x и перевод на корутины вместо старых `AsyncTask`.

**Практический план:** взять `Parser.java` и `Tags.java` как основу кодека (сверив с актуальной MS-ASWBXML), а логику команд написать заново — она проще кодека и у вас уже отлажена.

### Референсы на других языках
Если что-то в спецификации непонятно, полезно посмотреть, как сделано в живых реализациях:
- <cite index="18-1">Horde ActiveSync (PHP) — поддерживает версии 2.5, 12.0, 12.1, 14.0, 14.1, 16.0, включает согласование версии протокола и управление состоянием устройства</cite>;
- <cite index="19-1">go-activesync — библиотека на Go для EAS 14.1: WBXML-кодек, Autodiscover, Provision, FolderSync, Sync и Ping, разработана от спецификаций MS-ASWBXML / MS-ASCMD / MS-ASHTTP</cite>;
- <cite index="22-1">pyactivesync — клиент на Python для EAS 16.1, реализует MS-ASCMD и MS-ASWBXML: список папок, синхронизация почты, вложения, отправка, управление папками, перемещение, поиск по каталогу и push через Ping</cite>.

Ваша Flutter-реализация (`wbxml_codec.dart`, 626 строк) — тоже полноценный референс: она уже содержит нужные кодовые страницы и проверена на вашем сервере.

## 4. OAuth

| Задача | Библиотека |
|---|---|
| OAuth 2.0 + PKCE в браузере | **AppAuth for Android** (`net.openid:appauth`) — стандарт де-факто |
| Microsoft-аккаунты | **MSAL** (`com.microsoft.identity.client:msal`) — если понадобится Exchange Online |
| Хранение токенов | `EncryptedSharedPreferences` (androidx.security-crypto) |

Ваш OAuth-прокси при этом остаётся: он нужен, чтобы `client_secret` не попадал в APK. AppAuth работает с ним так же, как сейчас работает Flutter-версия.

## 6. Что меняется в плане работ

Оценка из `KOTLIN_DEV_GUIDE.md` была 9–14 месяцев. С учётом готовых компонентов:

| Этап | Было | Стало | Почему |
|---|---|---|---|
| WBXML + EAS | 6–8 нед | **4–6 нед** | Кодек из AOSP вместо написания с нуля |
| IMAP/SMTP | 2 нед | **1 нед** | Jakarta Mail вместо своей реализации |
| EWS | 3–4 нед | 3–4 нед | Без изменений — своя реализация |

Экономия около месяца. Общая оценка: **8–13 месяцев**.

**Порядок первых шагов уточняется:**
1. Выяснить вопрос лицензирования EAS (юридический, идёт параллельно).
2. Подключить Jakarta Mail, проверить IMAP на любом ящике — быстрая проверка, что каркас работает.
3. Взять `Parser.java` и `Tags.java` из AOSP, обновить под 14.1, покрыть тестами.
4. Provision + FolderSync на боевом Exchange.

Шаг 4 остаётся решающим: если EAS не пойдёт, дальше двигаться незачем.
