# Task S1: Siri / Shortcuts (iOS App Intents) and Android App Actions

Owner's request (31.10.2026), Ogneliss Mail 1.9.x. Existing: home-screen quick actions in lib/core/platform/app_shortcuts.dart (quick_actions plugin: «Мой день», «Написать письмо», «Создать встречу», «Создать напоминание») and deep-link/open paths (grep for how they route: /compose, /calendar, /my-day, mailto handling, the /message/... open path). The app's iOS Runner target has these Swift files already in project.pbxproj: AppDelegate.swift, DeviceCalendarPlugin.swift, DeviceContactsPlugin.swift, PhoneMirrorPlugin.swift, WidgetBridgePlugin.swift — new Swift code goes ONLY into one of these (no new files; project.pbxproj must not change).

## iOS (iOS 16+, availability-guarded; the app's minimum iOS may be lower)
- App Intents + AppShortcutsProvider (works without any entitlement): «Новое письмо» (optional recipient and subject parameters), «Новая встреча» (phrase parameter → use the app's quick-event phrase parser on the Flutter side: lib/features/calendar/quick_event.dart), «Новое напоминание» (phrase → task quick parser), «Мой день», «Непрочитанные» / «Письма от VIP» (open the corresponding screen/filter), «Найти в почте» (query parameter → search screen).
- Intents open the app (openAppWhenRun) and pass the action to Flutter via a MethodChannel or the existing deep-link route; if the Flutter engine is not ready yet, queue the action until it is.
- Phrases localised at least ru/en (AppShortcuts phrase strings must contain the app name token `\(.applicationName)`); other languages optional via Localizable strings if a strings file already exists — check ios/Runner for *.lproj; do not add new resource files that need project.pbxproj changes.
- Nothing for the owner in Xcode should be needed; if something is (e.g. the App Intents metadata extraction requires a build setting), write Russian instructions in docs/guides/IOS_SHORTCUTS.md.

## Android
- App Actions via res/xml/shortcuts.xml with `<capability>` elements for built-in intents where they fit (e.g. actions.intent.CREATE_MESSAGE is for messaging apps — check which BIIs exist and fit mail/calendar/tasks: actions.intent.CREATE_CALL no; actions.intent.GET_THING (search), actions.intent.OPEN_APP_FEATURE (feature names: «Мой день», «Непрочитанные», «Календарь», «Задачи», «VIP»), actions.intent.CREATE_THING / CREATE_TASK if available). Also static shortcuts in the same file for the four quick actions, so they appear for Assistant and the launcher. Reference it from the main activity's <meta-data android:name="android.app.shortcuts">. Make sure it does not conflict with the dynamic shortcuts already created by the quick_actions plugin (check the plugin's behaviour; dynamic + static coexist, max ~4–5 visible).
- Intents arrive as deep links (android:host/path) into the existing routing; parameters (query, feature) mapped to screens.
- Note in your report: Google is moving Assistant to Gemini; App Actions availability on a given device is up to Google. No paid services.

## Tests
Dart-side routing of incoming actions (unit/widget tests with fake method-channel calls), XML well-formedness test for shortcuts.xml (parse it in a test). Do not change the DB schema.
