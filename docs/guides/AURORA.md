# Ogneliss Mail для ОС «Аврора»: оценка и план

Решение владельца 03.11.2026: сделать версию для ОС «Аврора». На ней
работают корпоративные и государственные телефоны, а почтовых клиентов
с поддержкой Exchange там мало. Клиент остаётся бесплатным и с открытым
кодом.

Состояние на 03.11.2026. Сайты ОМП (developer.auroraos.ru,
omprussia.gitlab.io) из облачной среды разработки недоступны, поэтому
сведения — из поиска. Перед подключением их нужно сверить с первоисточником.

## 1. Flutter для «Авроры»

- Flutter для ОС «Аврора» выпускает ОМП четыре раза в год, с
  отставанием от основной версии. В архиве — 3.27.3, 3.29.2, 3.32.7,
  3.35.7, последняя — **3.41.4** (2026 год). Для сборки нужен Аврора
  Platform SDK, ОС «Аврора» — 5.1 и новее, пакеты RPM для armv7hl и
  aarch64.
- Наш код рассчитан на Flutter 3.47. **Проверено 03.11.2026:** код
  анализируется на Flutter 3.41.4 (Dart 3.11) без ошибок, зависимости
  подбираются (`flutter pub get`), код базы генерируется (build_runner).
  Пришлось одно изменение: перетаскивание в списках — через `onReorder`, а
  не через новое `onReorderItem` (его в 3.41 нет;
  `lib/core/utils/reorder_index.dart`). Осталось два предупреждения
  (импорт из `cupertino.dart` в `app_theme.dart`) — сборке не мешают.
- **1.15.0:** пакет super_drag_and_drop 0.10.0-dev (перетаскивание
  вложений) требует Flutter 3.44+ и Rust; для «Авроры» его нужно исключить
  (`dependency_overrides` или условная зависимость в сборке для «Авроры»)
  и выключить перетаскивание по признаку «Аврора» (раздел 4, п. 2):
  Flutter на «Авроре» называет платформу linux, а для linux
  `AttachmentDragOut.supportedOn` и `FileDropZone` включены.
- Правило на будущее: не использовать API Flutter новее версии для
  «Авроры» без запасного пути. Проверка — `flutter analyze` на её версии
  (в CI — шаг сборки для «Авроры», раздел 5).

| Плагин | На «Авроре» | Что делаем |

| path_provider, shared_preferences | есть (ОМП) | подключить порт |
| device_info_plus, package_info_plus, connectivity_plus | есть или в работе (plus_plugins ОМП) | проверить и подключить |
| flutter_secure_storage | не подтверждено | пароли ящиков — только в защищённом хранилище; без порта «Аврору» не выпускать |
| flutter_local_notifications | не подтверждено | без уведомлений — только ручная проверка почты |
| url_launcher, file_picker, share_plus | не подтверждено (`file_picker` и `share_plus` просили портировать; есть `pickers_aurora`) | проверить; без них — нет вложений из файлов и «Поделиться» |
| flutter_inappwebview | нет | письма показываются без WebView — тот же путь, что на Linux (`MailNativeBody`); WebView ОМП (webview_flutter 4.10) — позже |

| flutter_appauth, flutter_web_auth_2 | не подтверждено | Exchange и IMAP по паролю работают без них; вход Google и Microsoft — позже |

## 4. Главные технические риски

1. **База писем.** Пакет `sqlite3` 3.x собирает SQLite3MultipleCiphers
   (шифрование базы) build-хуком. Работают ли build-хуки при сборке под
   «Аврору» — неизвестно. Это проверяется первой пробной сборкой. Если не
   работают — системный SQLite «Авроры» с SQLCipher или другой способ
   шифрования (решать отдельно, база без шифрования — не вариант).
2. **Определение платформы.** Код для Linux (окно, трей, перетаскивание
   файлов) не должен работать на «Авроре». Нужен признак «это „Аврора“» —
   как его даёт Flutter для «Авроры», проверить по документации ОМП.
3. **Фон и уведомления.** Без `workmanager` и push почта проверяется,
   только пока приложение открыто. Фоновую работу и уведомления
   «Авроры» — следующим шагом.
