# Проверка кода: безопасность, быстродействие, параллельность, фон, нормы

Проверка по фактическому коду (не общий чек-лист), с конкретными файлами.
Ограничение среды: нет Dart SDK и устройства — проверка статическая и по логике;
рантайм-профилирование и прогон на боевых серверах остаются за вами.

Легенда: 🟢 в порядке · 🟡 замечание/рекомендация · 🔴 исправлено в этом заходе.

---

## 1. Безопасность

🟢 **Проверка TLS не отключена.** Все три `badCertificateCallback`
(`ntlm_client`, `app_http_overrides`, `corporate_http_client_io`) НЕ содержат
слепого `return true`: делегируют в `CertificatePinningService.evaluate` и по
умолчанию возвращают `false` (отклонить) до инициализации. Режим по умолчанию —
`trustStore` (не `off`), пиннинг по SHA-256 доступен.

🟢 **Учётные данные и БД.** Пароли/токены — во `FlutterSecureStorage`
(Keychain / EncryptedSharedPreferences), локальная БД шифруется. Подписи/данные
при удалении аккаунта и remote wipe действительно стираются.

🟢 **SQL-инъекций нет.** Единственная интерполяция в `customStatement`
(`app_database.dart:705`, `DROP TABLE IF EXISTS $t`) берёт `$t` из
захардкоженного списка таблиц — не пользовательский ввод.

🔴 **Утечка в логах OAuth — исправлено.** `oauth_proxy_client.dart:88,119`
логировали `resp.body` ответа `/token` при ошибке — тело может содержать токен.
Заменено на логирование только HTTP-статуса.

🟡 **Android network security config.** `network_security_config.xml`:
`cleartextTrafficPermitted="true"` глобально и доверие ВСЕМ user-CA. Для
корпоративного контура с собственным CA это осознанно, но лучше сузить cleartext
до конкретных доменов и запинить корпоративный CA (см. `PUBLISHING_COMPLIANCE.md`).

🟡 **Режим `trustStore` принимает любой валидный по системе сертификат на
доверенных доменах** без сверки отпечатка (модель «CA установлен в системе»).
Для боевого контура надёжнее `pinned` с отпечатками mail/oauth-серверов.

🟡 **Устаревший комментарий** в `corporate_http_client_io.dart` упоминает
`example.com` — код при этом корректно отклоняет (`return false`). Косметика.

## 2. Быстродействие

🟢 **Тяжёлый ИИ — в изоляте.** Анализ писем идёт через `compute(...)`
(`ai_analyzer_service`), главный поток не блокируется. В `sync_service` тяжёлых
`jsonDecode`/`utf8.decode` на горячем пути практически нет.

🟢 **Параллелизм синка ограничен.** Синхронизация папок идёт пачками с лимитом
`_maxParallel` (`_activeRequests` + `whenComplete`), а не «все разом» — сервер не
заваливается, память под контролем.

🟢 **Нет RegExp в горячих циклах**; списки писем читаются из БД через `.watch()`
(реактивно), без ручного поллинга.

🟡 **Мелочь:** несколько `existsSync()` (compose, tray, share-intent) —
синхронные, но по одному файлу, влияние ничтожно. При желании — заменить на
асинхронный `exists()`.

## 3. Параллельная работа

🟢 **Защита от параллельного синка корректна.** `syncAll`/`syncAccount`:
`if (_isSyncing) return; _isSyncing = true;` — флаг ставится СРАЗУ после проверки,
без `await` между ними, поэтому в однопоточной модели Dart гонки нет.
`syncSingleFolder` защищён набором `_foldersSyncing`.

🔴 **Гонка дублирующихся push-подписок — исправлено.** В `_startEwsPush` /
`_startEasPush` / `startForAccount` между проверкой `_subs.containsKey` и
присвоением `_subs[id]` есть `await` (запрос папок, подписка). Два параллельных
`start()` (например, «резюме приложения» + «применение интервала») могли создать
дублирующие подписки/соединения. Добавлена синхронная «резервация»: набор
`_starting`, `if (containsKey || !_starting.add(id)) return;` + снятие в `finally`.

## 4. Фоновая работа

🟢 **Диспетчер реализован, не заглушка.** `callbackDispatcher` помечен
`@pragma('vm:entry-point')` (обязательно для фонового изолята), поднимает свой
`ProviderContainer`, БД и уведомления, синхронизирует. Push переподписывается
циклически с паузой при неуспехе.

🟢 **Расписание учитывает платформу.** Таймер приложения тянет любой интервал;
WorkManager — не чаще 15 мин (ограничение ОС, честно отражено в UI). Режим
«Никогда» гасит и опрос, и push.

🟡 **Проверяемо только на устройстве.** Фоновый синк при полностью закрытом
приложении и точность интервалов зависят от ОС/производителя (Doze,
энергосбережение Xiaomi/Huawei) — нужен прогон на реальных устройствах.

## 5. Соответствие современным нормам

🔴 **Устаревший `withOpacity` → `withValues` — исправлено.** Было ~7 вызовов в
5 файлах (баннеры встречи/безопасности, календарь, наряды); в остальном коде уже
использовался современный `withValues`. Убирает предупреждения `flutter analyze`
о deprecation.

🟢 **Чисто по маркерам:** ни одного `TODO/FIXME/HACK`, реальных `print()` нет
(совпадения — `thumbprint`). Логирование — через `AppLogger`.

🟡 **Прочее к вашему `flutter analyze`:** окончательный список deprecation/lints
даст сам анализатор на вашей стороне (например, актуальность версий пакетов,
`use_build_context_synchronously` в местах, где после `await` используется
`context`). Готов закрыть по выводу.

## Итог
Критичных уязвимостей не найдено. Самое существенное — потенциальная утечка тела
токена в логи и гонка push-подписок — **исправлено в этом заходе** вместе с
модернизацией `withOpacity`. Остальное — рекомендации по ужесточению (пиннинг,
сужение cleartext) и то, что проверяется только на устройстве/боевых серверах.

Исправлено: `oauth_proxy_client.dart`, `imap_push_service.dart`, 5 UI-файлов
(withValues). Все правки структурно проверены (баланс скобок, умный чекер — 0
расхождений).
