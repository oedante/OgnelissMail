5. **Разделы** — включение и настройки Календаря, Задач, Заметок,

6. **Конфиденциальность** — PIN, трекеры, антифишинг, BIMI, DLP,

7. **Данные и место** — хранилище, архив, резервная копия, поиск во

8. **Система и справка** — синхронизация, работа в фоне, совместимость,

## 9. Календарь и «Мой день» «как в CRM» — рекомендация

Да, стоит — но не «как почта» и не перекраивать всё сразу:

- **«Мой день» — шкала дня** (как Outlook «Мой день», Sunsama, Fantastical):
  вертикальная лента времени с линией «сейчас», встречи блоками,
  задачи без времени — сбоку, перетаскиваются на время (планирование
  блоками); утром — «план дня», вечером — «итоги» (сделано, перенести на
  завтра). Сверху — часы и погода (сделано).
- **Контроль и поручения** (как Bitrix24, amoCRM): поручения из письма
  (п. 10) — статусы «новое / в работе / на проверке / выполнено»,
  ответственные, сроки, просроченные — красным; доска уже есть.
- **Календарь** — оставить месяц/неделю/день, добавить вид «3 дня» и
  поиск свободного окна для встречи с коллегами (занятость EWS уже есть);
  карточка подготовки к встрече (участники, последняя переписка, файлы).

Порядок: сначала макеты (снимки) «Моего дня» шкалой — на согласование,
потом поручения, потом календарь. Объём — L по каждому.

## 10. Экспериментально: поручения из письма (Н по просьбе владельца, L)

На имеющемся протоколе: поручение = письмо исполнителю(ям) с меткой и
сроком + задача у себя «На контроле» (EAS Tasks / EWS Tasks / локально для
IMAP) + флажок с датой у письма. Исполнение — по ответу (связка
`thread_linker`, «Исполнено» в строке ответа) или по флажку «выполнено» в
общей папке Exchange. Подзадачи — отдельные письма-поручения со ссылкой на
родительское. Сначала — описание и макет на согласование.

## 11. Погода — вопросы владельца

- **Российский API или «по лицензии MIT/Apache».** MIT и Apache —
  лицензии кода, а погоде нужны данные. Яндекс Погода для бизнеса —
  только по договору: 7 дней теста, далее от 54 000 ₽/мес за 10 000
  запросов. Open-Meteo — бесплатно только некоммерчески, код сервера AGPL.
  MET Norway — бесплатно и для коммерческих приложений (CC BY 4.0) — его и
  оставили.
- **«Не передавать данные пользователей»** — сделано: прогноз и поиск
  города через прокси на сервере Ogneliss (`server/weather-proxy`), MET
  видит только сервер; Nominatim не используется. Нужно развернуть
  прокси (README рядом) и добавить текст в политику (docs/guides/WEATHER.md).

Без внешних серверов и без «большой» LLM: **Bergamot / Firefox
Translations** — локальные модели по ~20–40 МБ на пару языков, движок
MPL-2.0 (по CLAUDE.md — нужно решение владельца), качество близко к
облачным для пар с английским; русский ↔ английский есть. Второй путь —
Windows AI API, но только на Copilot+ PC. Рекомендация — Bergamot,
модели скачивать по требованию. **Владелец согласен (08.11.2026)** — делаем.

## 13. Внешний аудит (присланный владельцем) — что берём

Снимок в нём устарел (76 коммитов, 1.9.0). По пунктам:

- **Перестроить `lib/` по слоям** — не берём: протоколы уже вынесены в
  `packages/mail_engine` (EAS, EWS, IMAP/SMTP за общим `MailTransport`),
  UI отделён от движка; переписывание — недели и риск регрессий.
- **Offline-first** — уже так: письмо открывается из базы (медиана 58 мс
  по журналу владельца), очередь отправки, фоновая синхронизация.
- **IMAP: UIDVALIDITY, UIDNEXT, CONDSTORE, QRESYNC, IDLE, MOVE** — всё
  есть (проверено аудитом); THREAD/SORT не нужны — беседы строятся на
  устройстве.
- **Секреты** — в защищённом хранилище, база SQLCipher, PKCE, в журнале
  паролей и токенов нет (проверено). Берём: отзыв токенов Microsoft и
  Яндекса (п. 2).
- **Единые ошибки** — частично есть (`core/errors/app_exceptions.dart`);
  берём постепенно: понятные строки вместо «Bad state: …» (одна уже
  сделана по журналу).
- **Тесты и CI** — есть: ~1500 юнит-тестов, 140 виджетных, сборки всех
  платформ, эмулятор; берём: сценарии вход → синхронизация → отправка →
  удаление → без сети на тестовом ящике (п. 14).
- **CONTRIBUTING.md** — берём (S); SECURITY.md уже есть.
