# Task E2: on-device translation of messages (incoming and outgoing)

Owner's request (31.10.2026), Ogneliss Mail 1.9.x: "Перевод письма на устройстве (как входящих, так и исходящих если можно. То есть пользователь написал на русском и при нажатии кнопки перевёл на английский с возможностью оставить два текста)".

## Licensing first (owner's rule in CLAUDE.md)
Candidate engines (check terms yourself and record them in your report and docs/LICENSING.md):
- Android: Google ML Kit on-device Translation (`google_mlkit_translation` Flutter plugin, MIT; ML Kit SDK free under Google APIs terms; check the ML Kit translation attribution requirements — if attribution like "Переведено Google"/"Powered by Google Translate" is required, show it) and ML Kit Language ID for detecting the source language.
- iOS (and macOS if supported): Apple Translation framework (iOS 17.4+/18, TranslationSession through SwiftUI `.translationTask`; host it in a hidden UIHostingController). Swift code must go into an existing Swift file of the Runner target (see common rules). Check the minimum iOS version of the app (ios/Podfile, Info.plist) and use availability checks.
- Windows/Linux/web: if there is no free on-device engine, hide the feature there.
If anything turns out paid or with unclear terms, stop and report instead of adding it.

## 1. Incoming
- In the message screen (lib/features/mail/screens/mail_detail_screen.dart): when the detected message language differs from the app language, show a small "Перевести с <язык>" chip/banner (like Gmail/Telegram); also a "Перевести" action in the message menu. Translated view replaces the body text (keep layout reasonable): for HTML mails translate text nodes and re-render (do NOT send HTML through the translator as one string; translate text segments and put them back; skip <style>, <script>, code/pre; keep links). "Показать оригинал" toggles back. Language models download on first use with progress and a Wi-Fi-only choice; show size if available.
- Works for HTML (WebView) and native/plain bodies. Cache translations in memory per message for the session.

## 2. Outgoing
- In compose (lib/features/compose/screens/compose_screen.dart; HTML editor lib/features/compose/widgets/mail_editor.dart with a JS bridge assets/editor/bridge.js; plain field fallback): a "Перевести" action in the compose menu/toolbar → choose target language (recent languages first; suggest the recipient's language if detectable from previous messages of the thread) → choose mode: "Заменить текст" or "Оставить оба текста" (original followed by the translation separated by a thin divider and a small language label, or translation first — let the user pick order; remember the last choice). Only the user's own new text is translated, not the quoted original or the signature (find how quote/signature are separated in the editor HTML).
- Undo should restore the original (editor undo if available or an explicit "Вернуть").

## 3. Settings
Mail settings: "Перевод" section — on/off for the incoming suggestion, never-translate languages, download/delete language models, Wi-Fi only.

## Tests
Unit tests for HTML text-segment extraction/reinsertion (structure preserved, links kept, scripts/styles untouched), compose "keep both" HTML assembly, language-choice logic. Use a fake translator interface so tests do not need ML models.

Do not change the DB schema.
