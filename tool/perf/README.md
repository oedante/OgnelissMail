# Замеры скорости на эмуляторе (tool/perf)

1.9.x, просьба владельца 31.10.2026. Задача `emulator` в
`.github/workflows/ci.yml` запускает `integration_test/emulator_test.dart`
на эмуляторе Android (API 34, x86_64, Pixel 6). Замеры —
`integration_test/perf_test.dart`:

| Замер | Что меряется |
|---|---|
| `mail_open_first_ms` | первое открытие письма в процессе: от «нажатия» (переход на экран письма) до показа текста; движок браузера ещё не загружен |
| `mail_open_ms` | повторное открытие (медиана трёх) |
| `mail_open_spare_ms` | открытие с запасным окном (MailWebViewPool), медиана трёх |
| `compose_first_ms` | первое «Новое сообщение» до готового редактора (файлы редактора читаются) |
| `compose_ms` | повторное (медиана трёх) |
| `compose_spare_ms` | с запасным окном редактора (MailEditorPool), медиана трёх |
| `app_first_frame_ms` | запуск без аккаунтов: от `main()` до первого кадра заставки |
| `app_first_screen_ms` | до первого экрана после заставки (заставка держится не меньше 1,8 с) |

У открытия письма в `perf-results.json` есть и этапы `OpenTrace` (окно,
создано, кадр, загрузка, текст) — по ним видно, что замедлилось.

Сборка отладочная (`flutter test` на устройстве другой не делает), графика
программная, процессоры общие: числа больше, чем на телефоне, и шумят.
Поэтому ошибка — только если замер **больше базы вдвое**; медленнее базы,
но меньше чем вдвое, — предупреждение в сводке.

## Запуск

- GitHub: Actions → CI/CD → Run workflow → отметка «emulator» (и на каждой
  метке `v*`). Результат — таблица в сводке сборки и `perf-results.json` в
  Artifacts (`emulator-<коммит>`).
- Локально (эмулятор или телефон подключён, `adb devices` его видит):
  `bash tool/dev/emulator_tests.sh [устройство]`, затем
  `python3 tool/perf/perf_check.py extract emulator-machine.jsonl emulator-logcat.txt -o perf-results.json`
  и `python3 tool/perf/perf_check.py compare perf-results.json`.

## Обновить базу

База — `tool/perf/baseline.json`. Начальные значения взяты с запасом, до
первого прогона на GitHub. Обновлять после первого удачного прогона и
когда скорость сознательно изменилась (ускорили — база ниже, иначе
замедление снова пройдёт незамеченным; осознанно замедлили — выше):

1. Скачать `perf-results.json` из Artifacts удачной сборки `emulator`.
2. `python3 tool/perf/perf_check.py baseline perf-results.json` — база =
   замеры × 1,5, вверх до 50 мс (`--headroom`, `--step`).
3. Проверить разницу (`git diff tool/perf/baseline.json`) и записать её
   отдельным коммитом с причиной.

Новый замер в тесте без строки в базе отмечается «🆕» и ошибкой не
считается; строка базы без замера — предупреждение.
