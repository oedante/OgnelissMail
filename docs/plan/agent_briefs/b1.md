# Task B1: sender logos via BIMI

Owner's request (31.10.2026), Ogneliss Mail 1.9.x: show brand logos for verified senders like Gmail/Apple Mail (BIMI). Avatars: lib/features/mail/widgets/email_list_tile.dart and wherever sender avatars are drawn (grep for initials avatar widget), message header in lib/features/mail/screens/mail_detail_screen.dart. Sender checks: lib/services/security/sender_safety_service.dart; IMAP already fetches the Authentication-Results header (lib/services/mail/imap/imap_service.dart ~line 696; check where it is stored).

## Rules (BIMI spec, simplified and safe)
- Show a logo only when the message passed DMARC for the From domain (Authentication-Results dmarc=pass from the receiving server — trust only the topmost header added by the user's own provider, not headers added earlier in the chain) AND the domain's DMARC policy is p=quarantine or p=reject (BIMI requirement).
- Fetch the BIMI record: TXT `default._bimi.<org domain>` (selector from BIMI-Selector header if present), `v=BIMI1; l=<https svg url>; a=<vmc url>`. SVG must be HTTPS, ≤ 32 KB, SVG Tiny PS profile — reject scripts, external refs, foreignObject; render with a safe renderer (check if flutter_svg is already a dependency; if you add it, check its licence — MIT expected). VMC validation (certificate chain) is optional: if you do not implement it, show the logo without any "verified" checkmark, and do not claim verification in UI text.
- DNS lookups go through the OWNER's server (decided with the owner 31.10.2026: no public DoH, sender domains must not go to third parties). Add an endpoint to server/oauth-proxy (Node + Express; read server.js, its auth with the app key header and BASE_PATH routing, README.md, install/reinstall scripts): `GET /bimi?d=<domain>` → the server resolves `_dmarc.<org domain>` and `default._bimi.<org domain>` (or the selector) with node's built-in `dns.promises.resolveTxt` (no new npm deps), fetches the SVG over HTTPS (timeout 5 s, ≤ 32 KB, no redirects to non-HTTPS), sanitises it with a strict allowlist (SVG Tiny PS elements/attributes only: no script, no foreignObject, no external href/url(), no event handlers, no style with url()), and answers JSON `{policy:"reject|quarantine|none|null", logo:"<sanitised svg>"|null}`. Shared server cache (memory + small JSON/disk file): positive 7 days, negative 1 day, cap entries. Rate-limit per client like other endpoints. No logging of domains — counters only (same privacy stance as server/push-relay README). Update server README (Russian) and the privacy note.
- Client: base URL from the existing OAUTH_PROXY_URL dart-define (see how the app calls the proxy, with OAUTH_PROXY_KEY); if not configured → feature unavailable. Setting "Логотипы отправителей (BIMI)" (appearance or privacy settings) default ON when the server is configured, with a one-line explanation ("домен отправителя проверяется через сервер Ogneliss, адреса и письма не передаются"). The client re-validates the SVG with the same allowlist before rendering.
- Cache per domain (positive and negative) on disk with TTL (e.g. 7 days positive, 1 day negative) — shared_preferences or a small file cache, NOT the drift DB schema. Never block list scrolling: lookups async and rate-limited; show initials until the logo is ready.
- Logo replaces the initials avatar in the list, conversation and message header (round mask, white background for transparent SVGs in dark theme).
