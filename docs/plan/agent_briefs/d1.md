# Task D1: iPad and desktop — drag and drop, resizable panes, message in a separate window

Owner's request (31.10.2026), Ogneliss Mail 1.9.x. Layouts: find the tablet/desktop multi-pane shell (grep for LayoutBuilder breakpoints, "wide", "desktop", NavigationRail in lib/core/navigation/ and lib/features/mail/screens/mail_list_screen.dart, desktop_mail_body.dart). Drawer/folder list: lib/features/mail/widgets/mail_drawer.dart. Moving messages: find the existing "move to folder" action (email actions service) and reuse it.

## 1. Drag messages to folders (tablet and desktop; also phone long-press drag is NOT required)
- In wide layouts, a mail row (and a multi-selection) can be dragged onto a folder in the folder pane/drawer or onto the archive/trash targets; drop → existing move action with undo snackbar. Visual feedback: drag avatar "N писем", highlighted target folder, invalid targets (other account's folders) disabled. Use Flutter's Draggable/LongPressDraggable/DragTarget — no new dependency. On desktop start the drag with a mouse drag (no long press); on iPad a long press then drag.

## 2. Drop files into compose (desktop + iPad)
- Dropping files from Finder/Explorer/Files onto the compose window adds attachments; dropping images into the editor body inserts them inline if the editor supports it (check MailEditor pickImage path). For desktop OS file drops you need a plugin: check `desktop_drop` (pub.dev, licence must be checked — MIT/BSD expected) or `super_drag_and_drop` (MIT, but uses Rust native code with prebuilt binaries — avoid unless needed). For iPad, check what Flutter supports natively; if it needs a plugin with unclear licence or heavy native build, skip iPad and report.
- Dragging attachments OUT of the app to Finder/Explorer: only if a plugin with a compatible licence makes it simple; otherwise skip and report (the "Save" action already exists).

## 3. Resizable panes (desktop + tablet landscape)
- The splitter between folder list / message list / message view can be dragged with the mouse (and finger on iPad), with min/max widths, double-click to reset; widths persist in settings (shared preferences). Cursor changes to resize on hover on desktop.

## 4. Message in a separate window (desktop: Windows, macOS, Linux)
- "Открыть в отдельном окне" in the message menu (desktop only). Implementing multiple Flutter windows: check `desktop_multi_window` (licence!) — it creates a second Flutter engine; the second window cannot share the Riverpod container or the drift database connection directly. Design: the new window gets the already prepared message content (headers + sanitised HTML/text + attachment metadata) as JSON through the plugin's method channel and renders a read-only view (reuse widgets that do not need providers, or a minimal provider scope), with buttons that send actions back to the main window (reply, forward, delete) via the channel. If this turns out too heavy or fragile, implement instead a detachable in-app floating window (an overlay panel that can be moved/resized) and report why.
- iPad: separate windows (multiple scenes) are out of scope — report.

## Tests
Widget tests for drag-to-folder (drop calls the move action, invalid target refused), splitter (drag changes width within limits, persisted), drop-into-compose (fake drop event adds attachment), and the window payload serialisation. Screenshot shots at 1280×800 and iPad landscape if cheap. Do not change the DB schema.
