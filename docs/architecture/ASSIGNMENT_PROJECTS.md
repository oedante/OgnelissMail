# Поручения: проекты с этапами (12.11.2026, дополнено 13.11.2026)

Просьба владельца 12.11.2026: в поручении — не только исполнители и
подзадачи, а этапы с ролями, файлами, сроками (последовательно или
параллельно), диаграмма Ганта и передача для исполнения. Ответы владельца:
этап «после N» уходит сразу с пометкой «начать после этапа N», а когда этап
N принят — письмо «Можно начинать»; при передаче «Готово» отправляет
основной исполнитель, соисполнитель сообщает о ходе работ. Дополнительно
выбраны: наблюдатели, чек-лист в этапе, прогресс и сдвиг сроков, шаблоны
проектов.

Транспорт прежний (`TASK_WORKFLOW_DESIGN.md`, решения 1 и 4): только
обычные адресованные письма, общего хранилища нет — у каждого участника
состояние собирается из его почты.

## 1. Что взято из аналогов

| Аналог | Что взяли | Что не взяли |
|---|---|---|
| Jira | Роли «исполнитель», «наблюдатели» (Watchers), чек-лист в задаче, прогресс эпика по задачам | Свои статусы и схемы переходов — у нас прежние шаги «Поручено → В работе → На проверке → Выполнено» |
| Битрикс24 | «Постановщик», «соисполнители», «наблюдатели»; «контролирующий» принимает работу; шаблоны задач | Учёт времени, оценки |
| MS Project | Диаграмма Ганта; связь «окончание → начало»; сдвиг последующих этапов при опоздании с сохранением длительности | Ресурсы, загрузка, критический путь, перетаскивание полос |

## 2. Модель

- **Проект** — строка `Assignments` с `isProject = true`: название,
  описание, начало (`startAt`), срок (по последнему этапу), файлы, план
  (`planJson` — этапы для участников), наблюдатели проекта.
- **Этап** — строка `Assignments` с `parentAssignmentId` = проект:
  - роли (`AssignmentParticipants.role`): постановщик 0, исполнитель 1,
    соисполнитель 2, наблюдатель 3, контролирующий 4, заместитель
    постановщика 5 (13.11.2026: те же права, что у постановщика);
  - `startAt`, `dueAt`; `afterId` — «начать после этапа» (окончание →
    начало), без него — параллельно; `stageOrder` — порядок в плане;
  - `checklistJson` — пункты `[{t, d}]`; `filesJson` — файлы `[{n, s, p |
    m, a}]`: свои (путь в папке приложения `assignment_files/<id>/`) и из
    писем (письмо и вложение);
  - `waiting` — этап ждёт предыдущий (до «Можно начинать»).
- **Шаблоны** — таблица `AssignmentTemplates`: проект без файлов, даты —
  смещениями в днях от начала (`ProjectDraft.toTemplateJson`).
- База — версия 30: в 29 — столбцы проектов и таблица шаблонов; в 30
  (13.11.2026) — `revision` (время последних полных сведений, секунды
  Unix) и `visibility` (0 — участники видят весь план и ход работ, 1 —
  каждый только свои этапы).
- Удалённый из проекта этап — снят и `isArchived` (в списках и плане его
  нет, строка остаётся).

Принимает работу этапа контролирующий, а без него — постановщик или
заместитель (`AssignmentView.iAccept`; у заместителя `outgoing` тоже true,
`iOwn` — только у самого постановщика). «Готово» отправляет основной исполнитель;
соисполнитель — «Сообщить о ходе работ» (отметки чек-листа и комментарий).

## 3. Письма

Скрытые отметки (`assignment_codec.dart`), всё остальное — обычный текст
письма на языке постановщика:

| Отметка | Поля | Когда |
|---|---|---|
| `data-ogneliss-task` | `pj` проект, `pa` родитель, `st`/`due` даты, `af` после, `ord` порядок, `to`, `co`, `ctl`, `obs`, `ti` название, `ck` чек-лист (`\|`), `pl` план (base64url JSON); полные сведения (13.11.2026): `rv` время, `de` описание, `ow` постановщик, `dep` заместители, `rm=1` этап удалён, `vis` видимость, `fn` имена файлов | письмо проекта, письмо этапа, передача, сдвиг сроков, изменение, ход работ, права |
| `data-ogneliss-status` | `st` статус, `ck` отметки чек-листа «0110», `go=1` «Можно начинать» | ответы, ход работ, «Можно начинать» |
| `data-ogneliss-people` | адрес, роль, имя | передача для исполнения (новый соисполнитель) |

- **Создание проекта** (`AssignmentService.createProject`): письмо проекта с
  планом — всем участникам (исполнители — «Кому», контролирующие и
  наблюдатели — «Копия»), затем по письму на каждый этап: исполнителю и
  соисполнителям, в копии — контролирующий и наблюдатели, файлы этапа —
  вложениями. Этап «после N» уходит сразу, со строкой «Начать после этапа
  N: когда его примут, придёт письмо „Можно начинать“».
- **«Можно начинать»** (`dispatchPending`, после каждой синхронизации):
  этапы моих проектов с `waiting`, чей предыдущий этап принят, — письмо
  исполнителю с `go=1`; у исполнителя этап перестаёт ждать.
- **Передача для исполнения** (`delegate`): исполнитель выбирает человека —
  тот получает этап целиком (отметка этапа + отметка участника), в копии —
  постановщик и контролирующий; у всех он добавляется соисполнителем,
  исполнитель остаётся прежним.
- **Ход работ** (`reportProgress`): отметки чек-листа строкой и комментарий
  — постановщику и контролирующему.
- **Файлы** (`addFiles`): письмо другой стороне с вложениями; вложения
  любого письма по этапу добавляются в его файлы.
- **Статус проекта** — по этапам (`projectStatus`): хоть один начат — «В
  работе», все приняты — «Выполнено»; у постановщика такой проект
  закрывается сам (без писем). Опаздывающий этап делает проект
  просроченным в списке.
- **Сдвиг сроков** (`shiftLate`): постановщик видит «Этап опаздывает» и
  нажимает «Сдвинуть»; последующие этапы цепочки получают новые даты
  (длительность сохраняется) и письмо с ними.

### Общий план, изменение, права (13.11.2026)

- **План для всех** (`visibility = 0`, по умолчанию): в плане письма
  проекта у этапа — исполнитель с именем, сроки, «после этапа» и статус.
  Когда у этапов меняются статусы, сроки, исполнители или порядок,
  постановщик (`iOwn`, не заместитель — без повторов) после синхронизации
  рассылает всем участникам письмо «Ход работ по проекту» с планом
  (`_broadcastProjects` в `dispatchPending`; подпись плана —
  `PlanStage.signature`, ход по чек-листу в неё не входит). Видимость
  «только свои этапы» (`visibility = 1`) — план не рассылается.
- **Изменение** (`editTask`, `updateProject`): постановщик или заместитель
  меняет название, описание, сроки, порядок, исполнителя, соисполнителей,
  контролирующего, наблюдателей, чек-лист, файлы; у проекта — ещё
  видимость и этапы (новые — `addStage`, удалённые — `removeStage`). Письмо
  — что изменилось списком и полные сведения (`rv`); у получателя они
  заменяют прежние, если новее (`_applyRevision`), отметки выполненных
  пунктов чек-листа сохраняются (`mergeChecklist`). Прежний исполнитель,
  которого заменили, получает то же письмо — у него поручение снято.
- **Права постановщика** (`grantRights`, `revokeRights`): заместитель —
  права у обоих (начальник и заместитель); «Передать полностью» (смена
  вахты) — постановщиком становится другой, прежний — наблюдателем. Новому
  — полные сведения: у проекта план со всеми подробностями этапов, этапы
  появляются у него целиком (`_stagesFromPlan`); остальным — кто теперь с
  правами. Ответы исполнителя уходят постановщику и всем заместителям;
  «Можно начинать» — от постановщика, а от заместителя — когда предыдущий
  этап принял он сам.
- **Напоминания о сроке** (`ReminderSchedulerService._scheduleAssignments`):
  исполнителю — накануне и в день срока, постановщику и контролирующему —
  утром после срока, если работа не сдана; настройка «Сроки поручений» в
  настройках задач.

Разбор (`AssignmentStore._apply`): новое поручение принимается, если я —
исполнитель, соисполнитель, контролирующий, наблюдатель, заместитель или
постановщик этапа, или получатель письма проекта. Сведения и сроки
применяются только из писем постановщика и заместителей. Чужой этап в копии (без роли) не появляется.
Отметки читаются только из свежей части письма (не из цитаты).

## 4. Экраны

- **«Поручения»**: кнопка «Новый проект» в шапке; в «Поручить» —
  «Сделать проектом с этапами» (переносит введённое). Строка проекта —
  «Этапы: 2 из 5» и полоса прогресса; этапы своего проекта — внутри
  проекта, не отдельными строками. Фильтры «Контролирую» и «Наблюдаю»
  появляются, когда такие есть; в строке чужого поручения — своя роль.
- **Новый проект** (`project_editor.dart`): название, описание, начало,
  контролирующий и наблюдатели проекта, файлы проекта, этапы (исполнитель,
  соисполнители, контролирующий, наблюдатели, «параллельно» или «после
  этапа N», начало и срок, чек-лист, файлы), «Из шаблона», «Сохранить как
  шаблон», «Разослать участникам».
- **Проект** (`project_screen.dart`): прогресс, даты, баннер опоздания со
  «Сдвинуть»; вкладки «Этапы» (по плану: свои — карточками с ролью,
  сроками, «после этапа N», чек-листом и файлами; чужие у участника —
  строкой из плана — с именем и статусом), «План» (диаграмма Ганта,
  `gantt_chart.dart`), «Файлы» (проекта и этапов), «История» (проекта и
  этапов). Меню: «Изменить проект» (тот же редактор, «Сохранить и
  разослать»), «Права постановщика», «Сохранить как шаблон», «Снять
  проект».
- **Изменить поручение** (долгое нажатие или «⋮» → «Редактировать»,
  `assignment_edit.dart`): окно этапа с прежними данными; у поручения без
  проекта — без выбора порядка. «Права постановщика» — там же (у этапа —
  в проекте).
- **Этап** (`assignment_screen.dart`): роли, даты, «после этапа», чек-лист,
  файлы; кнопки по роли — исполнитель: «Взять», «Готово», «Передать для
  исполнения», «Сообщить о ходе работ»; соисполнитель: «Сообщить о ходе
  работ»; контролирующий (или постановщик без него): «Принять», «Вернуть».
  Пустые чек-лист и файлы — кнопками, без пустых разделов.

Диаграмма: полоса — от начала до срока, заливка — сделанная часть
(чек-лист или статус), красная рамка — срок прошёл, ромб — этап принят,
стрелки — «начать после», вертикальная линия — сегодня, выходные — фоном.

## 5. Ограничения (осознанно)

- Статусы чужих этапов у участника — из последнего письма «Ход работ»:
  обновляются, когда постановщик синхронизирует почту (общего хранилища
  нет).
- Перетаскивать полосы на диаграмме нельзя: сроки меняются в «Изменить»
  или «Сдвинуть».
- Шаблон не хранит файлы.
- Видимость — для всего проекта (не для отдельного этапа).
- Убранный из поручения файл у получателей исчезает из списка, но остаётся
  во вложениях прежнего письма.
- Два изменения одного поручения с разных телефонов в одну минуту —
  действует то, что пришло позже по времени изменения.
