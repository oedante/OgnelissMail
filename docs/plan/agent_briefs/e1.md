# Task E1: dates in message text, and creating a meeting from a plain phrase

Owner's request (31.10.2026), Ogneliss Mail 1.9.x.

## 1. Shared date/time phrase parser
There is lib/features/tasks/task_quick_parser.dart (ru/en: сегодня/завтра/послезавтра, weekdays, times, «через N …», recurrence). Generalise the date/time part into a shared, well-tested parser (e.g. lib/core/utils/date_phrase.dart) used by tasks, calendar and mail, without changing task quick-add behaviour (its existing tests must still pass). Support at least Russian and English well; numeric formats for all locales (31.10, 31.10.2026, 2026-10-31, 10/31 per locale, 15:00, 3 pm), month names ru/en (+ de/fr/es if cheap), ranges («с 15 до 16», «15:00–16:30», «on Nov 3 from 2 to 3pm»), durations («на час», «на 30 минут», «for 1 hour»), relative («завтра в 15», «в пятницу в 10», «next Monday»). Resolve relative to a given reference time (the message date for mail text!) and the device time zone.

## 2. Dates in message text (like iOS data detectors)
- Detect date/time mentions in the message body and make them tappable: in the native body (lib/features/mail/widgets/mail_native_body.dart), in plain-text mails (LinkifiedText, lib/features/mail/widgets/linkified_text.dart) and in HTML mails rendered in the WebView (lib/features/mail/widgets/mail_html_view.dart: MailHtmlDocument.build already turns plain-text URLs/emails into links via _linkifyText — add dates the same way, as links with a private scheme, e.g. `ogdate:...`, handled where link taps are handled — find shouldOverrideUrlLoading / link opener; JS is disabled in the Android mail WebView, so links only).
- Do not touch text inside existing <a>, <style>, <script>, quoted history may stay detectable. Avoid false positives: plain numbers, versions (1.9.0), prices, phone numbers, order IDs — require a time or a clear date shape. Reference date = message date (so «завтра» means the day after the message was sent).
- Tap → a card-style sheet (reuse showChoiceSheet style used elsewhere) with: "Создать встречу" (opens the calendar event editor prefilled: title = message subject, start/end, description with a link back to the message if there is such a mechanism), "Напоминание" (task with due date), "Скопировать", "Показать в календаре" (the day).
- Setting toggle "Даты в тексте письма" (default on) in mail settings.
- Performance: detection runs where the document is built (isolate/work_isolate already used for building); must not slow down opening mail noticeably — benchmark on a long newsletter in a unit test (time budget).

## 3. Meeting from a plain phrase (like Fantastical)
- In the calendar (lib/features/calendar/screens/create_event_screen.dart and calendar_screen.dart) add a quick-add field: «Созвон с Анной в пятницу в 15 на час» → event title «Созвон с Анной», Friday 15:00–16:00; «Обед завтра 13:00-14:00 в кафе «Ромашка»» → location if «в …» after time is clearly a place (keep it conservative). Show a live preview of the parsed result before creating; Enter/“Создать” creates, “Подробнее” opens the full editor prefilled.
- Also accept the phrase in the existing "new event" entry points on phone, tablet, desktop (find FAB / menu entries).

## Tests
Extensive unit tests for the parser (ru/en, numeric, ranges, durations, relative to a reference date incl. year wrap, DST-safe), detection in text (positives and negatives listed above), HTML linkify of dates (no changes inside <a>), widget test for the quick-add preview.

Do not change the DB schema. Note: another change (dark mode / long message clipping) was just merged into mail_html_view.dart — rebase-friendly edits only.
