Read how sync currently works first (how flags/deletions of already-synced messages are refreshed, how new mail is detected, IDLE handling, Gmail specifics).

## 1. CONDSTORE (RFC 7162) and QRESYNC
- If the server advertises CONDSTORE: store per folder UIDVALIDITY and HIGHESTMODSEQ; on the next sync fetch only messages whose flags changed: `UID FETCH 1:* (FLAGS) (CHANGEDSINCE <modseq>)` (enough_mail: uidFetchMessages with changedSinceModSequence; selectMailbox with enableCondStore). Update stored modseq after a successful sync.
- If QRESYNC is advertised: `ENABLE QRESYNC`, SELECT with QRESYNC params (uidvalidity, modseq, known UIDs) to receive VANISHED (expunged UIDs) and changed flags in one round trip, instead of listing all UIDs to find deletions.
- UIDVALIDITY change → full resync (existing path). Any error/unexpected response → fall back to the existing full method for that folder and log once (no data loss, no crash).
- Typical servers: Gmail (CONDSTORE, no QRESYNC), iCloud, Yandex, Mail.ru, Fastmail, Dovecot (check what each advertises if you can find documentation; do not rely on it — always check CAPABILITY).
- DB: you may change the schema — use schema version 27 exactly (lib/data/database/app_database.dart, currently 26), with a migration (add nullable columns, e.g. on the folders table: highestModSeq, maybe uidValidity if not stored already) and a migration test like existing ones.

## 2. IMAP NOTIFY (RFC 5465)
- If the server advertises NOTIFY: one connection can watch all subscribed/synced folders (STATUS/MessageNew/MessageExpunge/FlagChange for INBOX and other folders) instead of IDLE on INBOX only. Use it in the existing push/IDLE loop when available; otherwise keep IDLE.
- enough_mail has no NOTIFY command. Check whether its public API lets you send a raw command and receive untagged responses (e.g. a generic sendCommand / a custom ResponseParser, or subclassing ImapClient like we subclass SmtpClient in packages/mail_engine/lib/src/transport/tolerant_smtp_client.dart). If it is not possible without modifying enough_mail, do NOT hack it: report clearly and skip NOTIFY.
