# Task N2: server wake-up signals for Android (like the existing iPhone push relay)

Owner's request (31.10.2026), Ogneliss Mail 1.9.x. Background: Android 15 limits dataSync foreground services to 6 h per day (android/app/src/main/kotlin/com/ogneliss/mail/SyncForegroundService.kt, lib/services/background/foreground_sync_controller.dart), Doze delays WorkManager checks. For iPhone the app already uses the owner's push relay: lib/services/push/push_wake_service.dart (client), server/push-relay (Node: server.js, README.md, install script, Dockerfile) — read them fully first; the relay only knows a device token, environment, interval, mode — never addresses, passwords or mail. Do the same for Android.

## Licensing / cost (owner's rule in CLAUDE.md)
Firebase Cloud Messaging is free; firebase_messaging / firebase_core Flutter plugins are BSD-3; Firebase Android SDK Apache-2.0 (depends on Google Play services — proprietary, free). Verify and record in docs/LICENSING.md. Optionally UnifiedPush (Apache-2.0) for devices without Google services — only if it is simple; otherwise note it as a follow-up.
- Avoid the google-services Gradle plugin and a committed google-services.json: initialise Firebase from dart-defines (config/dart_defines.json is how the app gets build-time config — find how DART_DEFINES / String.fromEnvironment are used, e.g. for OAuth client ids) with FirebaseOptions(apiKey, appId, messagingSenderId, projectId). If the defines are empty, Android push is simply unavailable and everything works as today. Check that adding firebase plugins does not break iOS/macOS/Windows/Linux builds (they must not require Firebase config there; if firebase_core forces CocoaPods changes for iOS, scope it to Android only or document what the owner must do).

## Client
- Extend PushWakeService (or add an Android counterpart sharing the registration protocol): get the FCM token, register it with the relay with platform=android, interval and mode, refresh daily, unregister when turned off. High-priority FCM data message → background handler (FirebaseMessaging.onBackgroundMessage, top-level, isolate) runs the same mail check as the iPhone wake (BackgroundService.runForPushWake or the Android background check path) within the time budget, then posts notifications as usual. Note FCM's rule: high-priority messages that do not lead to a user-visible notification may be deprioritised — document how the relay should use priority (e.g. normal priority for routine wakes) and be conservative.
- Settings: the existing push setting UI for iPhone (find it) shows on Android too when available ("Сигналы сервера").

## Server (server/push-relay)
- Add FCM HTTP v1 sending: OAuth2 access token from a service account JSON (sign the JWT with node's crypto — no new npm dependency if possible; if you add one, check its licence), POST to https://fcm.googleapis.com/v1/projects/<id>/messages:send with a data-only message, android.priority per mode, ttl. Handle UNREGISTERED/INVALID_ARGUMENT → delete token. Same storage file and privacy guarantees; update README.md (Russian) and the install script (new option --fcm-service-account path), docker-compose.
- Keep APNs behaviour unchanged. Add server tests if the project has any (check package.json); otherwise a small node test script.
